# Ferixdi AI — Telegram-бот с 14 мифами о Reels

Базовая воронка: /start → 14 мифов → реальные кейсы → интрига перед видео → исходный MP4 → кнопка на реальные кейсы.
Каждый шаг открывается одной кнопкой. Для начала бот не собирает личные данные и не требует базы данных.

## Запуск на Render Free

1. Открой https://dashboard.render.com/ и выбери **New → Blueprint**.
2. Подключи GitHub и выбери репозиторий **ferixdi-png/telegram**.
3. Render прочитает `render.yaml`. Выбери Free, если доступен.
4. Добавь в Render секрет **BOT_TOKEN** из BotFather (никогда не в GitHub).
5. Публичный адрес бот определяет автоматически по переменной Render `RENDER_EXTERNAL_HOSTNAME`. Вручную его вводить не нужно.
6. **WEBHOOK_SECRET** Render сгенерирует автоматически. Если создаёшь Web Service вручную, задай собственную случайную строку букв/цифр длиной от 32 символов.
7. Сделай Deploy/Redeploy и открой адрес сервиса. Должен ответить JSON `{"status":"ok","bot":"Ferixdi AI Reels"}`.
8. Открой своего бота в Telegram и введи `/start`.

Если Render запустился до ввода адреса или токена, добавь переменные в Environment и выбери Manual Deploy → Deploy latest commit.

## Где менять тексты

Все тексты, порядок кнопок и URL находятся в `content.py`.
Бот не хранит токен в коде. Бесплатный Render может засыпать после 15 минут без обращений, поэтому первый ответ иногда задерживается. Статистика пока только в технических логах, без постоянной аналитики.

## Финальное видео в оригинальном качестве (GitHub Releases)

Оригинальный MP4 (около 43 МБ) размещается как **Release asset**, отдельно от исходного кода. Бот скачивает файл на временный диск Render при первом запросе и отправляет как Telegram **Document** через `send_document`. Телеграм получает исходные байты без кодирования, сохраняя качество.

### Разовая загрузка исходного MP4

1. Открой **https://github.com/ferixdi-png/telegram/releases/new**.
2. Нажми **Choose a tag** → введи `video-v1` → **Create new tag: video-v1**.
3. Release title: `Оригинальное видео: процесс создания AI-Reels`.
4. На компьютере переименуй исходный `1007(9).mp4` в **`ferixdi-process.mp4`** (только имя, исходный контент не меняется).
5. Перетащи файл в блок **Attach binaries by dropping them here or selecting them**.
6. Дождись полной загрузки, затем нажми **Publish release** (публичный релиз, без галочки draft). Видео станет доступно по адресу:
   `https://github.com/ferixdi-png/telegram/releases/download/video-v1/ferixdi-process.mp4`
7. В Render выбери **Manual Deploy → Deploy latest commit** и дождись **Live**.
8. В Telegram отправь боту `/status`, затем проверь финальный переход на страницу кейсов.
9. Пройди воронку `/start` → 14 мифов → кейсы → видеотизер → оригинальный MP4 → сайт с кейсами.

**Переменная `VIDEO_FILE_ID` больше не требуется.** Если она сохранилась в Render, бот по-прежнему использует её в приоритете. Для переключения на GitHub Releases удали `VIDEO_FILE_ID`, сохрани настройки, дождись Live.

Файл при первом нажатии может загружаться с GitHub несколько секунд. Далее бот повторно использует Telegram file_id, пока сервис работает. После перезапуска Render файл скачивается повторно. Бесплатный диск Render временный.

### Команды для проверки

- `/start`: начало воронки.
- `/status`: версия бота (ожидается v2.3), выбранный источник видео.
- `/fileid`: резервный способ подключить документ через Telegram, если понадобится.

Не загружай исходный MP4 в папку репозитория через GitHub веб-интерфейс: там лимит файла 25 МБ. GitHub Releases подходит для исходника такого размера.
