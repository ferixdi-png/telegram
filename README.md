# Ferixdi AI — 16 мифов о Reels за 10 разборов

Базовая воронка: /start → 5 примеров Reels (ещё 6 по желанию) → 10 тематических разборов всех 16 мифов → реальные кейсы → исходный MP4 → сайт и компактное меню.
Каждый разбор открывается одной кнопкой. Теперь у каждого из десяти экранов есть подробное объяснение, что автор проверял, что увидел и как это соотносится с охватами. Галерея и ответы на вопросы доступны по желанию. Для начала бот не собирает личные данные и не требует базы данных.

## Запуск на Render Free

1. Открой https://dashboard.render.com/ и выбери **New → Blueprint**.
2. Подключи GitHub и выбери репозиторий **ferixdi-png/telegram**.
3. Render прочитает `render.yaml`. Выбери Free, если доступен.
4. Добавь в Render секрет **BOT_TOKEN** из BotFather (никогда не в GitHub).
5. Публичный адрес бот определяет автоматически по переменной Render `RENDER_EXTERNAL_HOSTNAME`. Вручную его вводить не нужно.
6. **WEBHOOK_SECRET** Render сгенерирует автоматически. Если создаёшь Web Service вручную, задай собственную случайную строку букв/цифр длиной от 32 символов.
7. Сделай Deploy/Redeploy и открой адрес сервиса. Должен ответить JSON `{"status":"ok","bot":"Ferixdi AI Reels"}`.
8. Открой ссылку `https://ferixdi-telegram.onrender.com/start`. Telegram откроет бота с кнопкой **Start / Запустить**; ручной ввод `/start` не требуется.

Если Render запустился до ввода адреса или токена, добавь переменные в Environment и выбери Manual Deploy → Deploy latest commit.

## Ссылка на запуск бота

**Основная:** https://ferixdi-telegram.onrender.com/start

На этом пути Render узнаёт публичный @username своего Telegram-бота через Bot API и перенаправляет на `https://t.me/<username>?start=ferixdi`. Так ссылка продолжит вести на правильного бота даже при изменении его username.

Техническое ограничение Telegram: ссылка с `?start=` открывает чат с кнопкой **Запустить / Start**, которую пользователь нажимает сам (особенно при первом запуске). После нажатия Telegram автоматически отправляет `/start ferixdi`; вручную писать команду человеку не требуется. Бот реагирует обычным стартовым приветствием.

Ссылка заработает после деплоя версии v4.28. Проверить готовность можно командой `/status` (`Ferixdi Bot v4.28`) и открытием маршрута в браузере. Render Free может просыпаться несколько десятков секунд.

**Ещё удобнее для рассылок:** после запуска v4.28 отправь своему боту `/link`. Он ответит настоящей короткой ссылкой `https://t.me/<его_username>?start=ferixdi`. Для Threads, Instagram и Telegram используй именно эту прямую ссылку — она ведёт в бот без промежуточного перехода через Render.

## Где менять тексты

Все тексты, порядок кнопок и URL находятся в `content.py`.
Бот хранит воронку из 10 углублённых разборов 16 мифов, включая экономику генерации и пользу AI-охватов для трафика. Бот не хранит токен в коде. Бесплатный Render может засыпать после 15 минут без обращений, поэтому первый ответ иногда задерживается. Статистика пока только в технических логах, без постоянной аналитики.

## Контент воронки

Последовательность: `/start` → первые пять визуальных примеров (остальные шесть по кнопке) → 10 тематических разборов 16 мифов → цифры собственных аккаунтов и учеников → исходный MP4 → сайт или необязательное меню.

Тексты и кнопки редактируются в `content.py`. Для читаемости применено HTML-форматирование Telegram: жирный заголовок, номер разбора `01/10`, короткие абзацы, одна кнопка. Содержимое полей `myth` и `answer` экранируется при отправке.

Стиль автора: тёплая живая беседа с подписчиком, от первого лица. Важны не продающие лозунги, а личные ошибки, наблюдения и проверяемые действия. Живой уверенный тон, уважение к читателю, иногда короткое эмоциональное слово капсом. В блоке о монетизации подчёркнуто: охваты это люди, переходы и возможные заявки, а не только красивый счётчик. В пользовательских сообщениях и кнопках исключены длинные тире, шаблонные маркетинговые фразы и отдельно стоящая частица «не». Прямое приглашение на обучение появляется лишь в добровольной ветке после просмотра видео. Цена и промокод остаются на сайте; прямой разговор о программе начинается только по выбору человека. В других ветках — поддержка уже обучающихся, спокойный ответ на вопрос о бюджете и вариант отложить решение. 

## Подборка Reels сразу после приветствия

Перед первым мифом показывается галерея из 11 скриншотов. Это результаты как аккаунтов автора, так и ребят, которые делают Reels по его системе. Скриншоты содержат **лайки, а не количество просмотров**. Для исходной подборки бот знает значения: 136 000, 109 000, 79 000, 71 800, 53 400, 46 400, 36 600, 28 700, 24 600, 23 300, 18 100. Он сортирует распознанные фото по этим значениям, причём проверенные совпадения имеют приоритет над устаревшей переменной `EXAMPLE_PHOTO_LIKES`. Для исходной подборки из 11 скринов код дополнительно хранит последовательность значений при первой загрузке. Поэтому при повторной отправке **тех же 11 скринов в той же последовательности** он сможет восстановить правильный порядок даже при новых Telegram ID. Если изображения заменили или перемешали, следует указать точные `EXAMPLE_PHOTO_LIKES` для нового списка: без них надёжно восстановить порядок невозможно. При частичном совпадении скриншоты сортируются по известным данным, а неизвестные временно уходят в конец. Первые пять показываются сразу, остальные шесть по кнопке. В тексте, который получает посетитель, порядок сортировки вообще не обсуждается. Полные Telegram file_id не публикуются в репозитории, сопоставление идёт по короткому отпечатку.

Для галереи используй свои 11 скриншотов с результатами. Бот теперь принимает PNG/JPG и как обычные фотографии, и как файлы-документы.

1. Дождись **Live** после обновления GitHub. Проверка `/status` должна показать `Ferixdi Bot v4.28`.
2. В Telegram отправь `/galleryclear`.
3. Заново отправь боту свои **11 скриншотов**. Можно как обычные фото, можно как PNG/JPG-файлы — бот сам подготовит изображения для галереи. Если отправляешь альбомом, Telegram ограничивает его десятью элементами: 10 + 1.
4. Дождись «Все 11 скриншотов на месте!» и отправь `/galleryids`. Подготовка PNG-документов может занять около минуты. Готовую строку из 11 Telegram `file_id` бот пришлёт отдельным сообщением.
5. В **Render → Environment** задай `EXAMPLE_PHOTO_IDS` равным всей строке `file_id` через запятую, без кавычек и пробелов. Сохрани настройки и дождись **Live**.
6. Проверь `/status`: там будет `Примеры: 11 фото` и диагностическая строка `Знакомые скрины: N/11`. Для точного порядка всех 11 нужно совпадение 11/11 либо правильно заданные значения для отсутствующих ID. Затем `/start` → `🔥 А какие ролики залетали?` → пять самых залайканных скринов → `🏁 Давай к мифам` или `📸 Ещё 6 скринов`.

Скриншоты, отправленные до v3.2 в качестве файлов, были отклонены старым обработчиком, поэтому их нужно отправить повторно. Команда `/galleryids` теперь преобразует PNG/JPG-документы в фототип Telegram и пытается убрать временные копии из чата после получения новых `file_id`. При повторной отправке одинаковых файлов бот отсеивает дубликаты по `file_unique_id`.

Для следующей подборки с другими скриншотами можно дополнительно указать `EXAMPLE_PHOTO_LIKES` через запятую, строго в том же порядке, что и `EXAMPLE_PHOTO_IDS`. Тогда бот отсортирует новый набор по этим значениям. Если значения отсутствуют, известная текущая подборка распознаётся и сортируется автоматически.

Если переменная не установлена, бот сразу направит пользователя к мифам. Если Telegram временно откажет в отправке изображений, бот продолжит путь с текстом. Чтобы заменить подборку, повтори процедуру с новыми изображениями.

## Новые мифы и финальные сценарии

Воронка охватывает все 16 мифов за 10 тематических разборов. Три последних разбора теперь сосредоточены на двух основных целях: **рост охватов и личного бренда**, а затем **партнёрки агрегаторов нейросетей** и потенциальные входящие запросы от заказчиков.

- Главное направление монетизации: партнёрские программы агрегаторов нейросетей. Автор описывает много таких сервисов и появление новых. По его ссылке в Syntx пришли 190+ человек; это показатель привлечения, а не сумма заработка.
- Личный бренд: аккаунт с охватными AI-роликами становится публичным портфолио, которое потенциально привлекает заказчиков на производство видео. Недвижимость остаётся второстепенной тестируемой партнёркой с долгим циклом сделки, без обещания комиссий.
- Финальный миф теперь посвящён практическим действиям после роста аккаунта: оформить профиль, показать лучшие ролики, подключить ссылки и анализировать переходы. В финальном мифе подробнее раскрыта дополнительная монетизация через собственное обучение: после реального роста в Instagram можно передавать другим практический навык создания охватных AI-роликов, подкрепляя его кейсами, системой генераций, публикаций и анализа статистики. Приоритетами остаются личный бренд и партнёрки агрегаторов нейросетей.

После выдачи MP4 пользователь получает две кнопки: прямой переход на сайт с кейсами или «А где узнать конкретные шаги?». Отдельная промежуточная карточка перед MP4 убрана: видео отправляется сразу по кнопке после кейсов.

Последняя кнопка раскрывает основной выбор: «Хочу разобраться глубже», «Я и так умею», «Есть сомнения», «Я уже в группе» и ссылку на кейсы. Креатор с опытом может сразу написать автору по поводу партнёрского трафика.

Ветка «Есть сомнения» открывает по запросу «Всё слишком сложно?», «Пока дороговато», «AI-рынок перегрет?», «С нуля уже поздно?» и «Вернусь позже». В первом случае бот объясняет готовую пошаговую систему: от идеи и инструментов до контента, аналитики и партнёрок. Отдельный сценарий «Я и так умею» предлагает показать переходы по ссылке в Instagram за 30 дней и обсудить трафик с автором в личных сообщениях. Сохраняются личный контакт [@ferixdiii](https://t.me/ferixdiii), информация о программе и кнопка возврата к вопросам.

Для быстрого прохождения 16 мифов объединены в 10 тематических карточек с прогрессом 01/10–10/10. Похожие вопросы идут вместе; реальные кейсы и видео — отдельными шагами.

Подтверждение фактического просмотра видео или сайта бот не проводит: кнопки отражают добровольный выбор пользователя.

## Методика и комфортный ритм публикаций (v4.28)

В обучающей ветке и ответе про бюджет генераций указан ориентир: **в среднем 100 ₽ в день с учётом выходных**, при наличии примерно двух часов для практики в рабочие дни. Выходные без публикаций сами по себе не означают, что после понедельника ролики перестанут получать охваты; это наблюдение автора по собственным кейсам, а не гарантия результата.

В конце блока о практических действиях добавлен главный принцип: система не требует каждый день придумывать креатив с полного нуля, она строится на повторяемых действиях. При этом собственное видение и доработка сильных форматов обязательны. Сочетание системы и творческого подхода помогает искать устойчивый рост охватов.

## Ускорение Telegram webhook и видео-кэша (v4.28)

- **Контент и последовательность экранов не менялись.** Все десять GIF, приветствие, галерея, блок об алгоритмах, исходный MP4, шрифт и кнопки используются в прежнем виде.
- Приложение теперь передаёт обновления Telegram в стандартную `Application.update_queue` и немедленно отвечает webhook `200 OK`. Долгие запросы к Telegram (например, первая загрузка GIF) больше не удерживают открытым входящий HTTP-запрос.
- `python-telegram-bot` обрабатывает до **8 обновлений параллельно**, поэтому тяжёлый файл одному посетителю меньше задерживает команды других.
- Кэш заранее скачанных MP4 теперь **не выбрасывает завершённые успешные загрузки** до их использования. Предзагрузка остаётся ограниченной двумя элементами, чтобы не раздувать память.
- Первый показ анимации после холодного перезапуска всё равно требует загрузки и преобразования MP4 Telegram. Без заранее сохранённого `INTRO_ANIMATION_ID` / `STEP_ANIMATION_NN` это ожидание устранить полностью нельзя. После первого показа повторные отправки используют Telegram ID и должны быть быстрее.

## Исправление ответа /start (v4.28)

Когда Render перезапускается после обновления, Telegram GIF вступления отсутствует во внутреннем кэше. Раньше `/start` ждал загрузки и конвертации исходного MP4 прямо внутри обработки webhook, из-за чего пользователь мог долго не видеть ответа, а Telegram мог повторить запрос по таймауту. Теперь команда `/start` обрабатывается с `block=False`: webhook подтверждается без ожидания MP4. На первом холодном запросе бот показывает временное «⏳ Загружаю приветствие», затем отправляет прежнюю анимацию и убирает временное сообщение. ## Кастомный шрифт заголовков через Telegram Emoji

Версия v4.28 использует кастомные буквы набора «Карандашик HD» для слова **МИФ** в заголовках всех десяти шагов: М = `5264807616227357702`, И = `5264908337505412642`, Ф = `5264998149566539809`. Все экранные тексты, десять GIF, номера и кнопки остаются прежними. Заголовок собирается в функции `page()` и применяется как к подписи GIF, так и к текстовому резервному сообщению. Если Telegram отклонит CustomEmoji у бота, он повторит отправку анимации с обычным словом «МИФ», сохраняя работу воронки. Команда `/emojifont` остаётся доступна для получения дополнительных букв. Уже отправленный в бота образец `М И Ф` можно использовать повторно: ответь на его сообщение **отдельной командой** `/emojifont МИФ`. Бот прочитает три `MessageEntity.CUSTOM_EMOJI`, покажет ID каждой буквы и попробует прислать тестовую надпись из тех же эмодзи.

ID букв М, И и Ф уже прописаны в коде. Для других слов можно получить новые буквы и ID отдельно; сейчас кастомный шрифт используется только для метки МИФ. Для будущих фраз собери соответствующие буквы из этого же набора и ответь командой `/emojifont СЛОВО`, строго в порядке букв.

Это кастомные эмодзи Telegram, а не обычные шрифты. Согласно Telegram Bot API, отправлять их ботом в личные чаты разрешено, когда владелец бота имеет Telegram Premium, либо с особыми правами коллекционного имени на Fragment. Если Telegram откажет в тестовой отправке, команда всё равно покажет ID и сообщит о проблеме. Получать сами ID можно и без автоматического включения их в воронку.

## Анимированное приветствие (до 11 скриншотов)

В v4.28 сам первый экран `/start` поддерживает **одну Telegram-анимацию + весь HTML-текст INTRO + стартовую кнопку** в одном сообщении. Исходный MP4 был получен в этом же Telegram-боте как документ, поэтому код конвертирует его в `send_animation` при первом показе, запоминает полученный Telegram `animation.file_id` в памяти и использует его для последующих пользователей. Проверка: дождись деплоя, отправь боту `/status` (v4.28), затем `/start`. При успехе появятся интро-анимация, полный приветственный текст и кнопка просмотра скриншотов. Если Telegram отклоняет конвертацию (например, MP4 слишком велик для `get_file` или файл содержит неподдерживаемую аудиодорожку), бот покажет прежний текст с кнопкой и запишет техническую причину в Render Logs. `/status` сообщает об источнике или готовом ID.

## Первый GIF уже подключён автоматически

Первый короткий MP4 для шага 01/10 ранее был отправлен пользователем в этот же Telegram-бот как документ, поэтому бот выдал обычный `VIDEO_FILE_ID`. **Это ID документа, а не GIF.** В v4.28 бот использует предоставленный ID как источник первого ролика, скачивает его через Telegram API и один раз загружает как Telegram-анимацию при первом открытии шага 01/10. Полученный animation `file_id` сохраняется в памяти процесса для следующих показов. Поскольку Render Free может перезапускаться, после перезапуска первый показ вновь конвертирует документ.

**Для первого экрана руками ничего добавлять в Render не требуется.** Код уже содержит источник; `STEP_ANIMATION_01` остаётся доступным как переопределение, если позже захочется закрепить animation file_id через Environment. Первый экран при успешной загрузке будет **одним сообщением: MP4-анимация без звука, полный текст и кнопка**. При ошибке Telegram бот сохранит текстовый вариант и запишет причину в Render Logs. Команда `/status` показывает, что источник первого GIF подключён, а после первого успешного просмотра появляется 1/10.

**Важно:** `VIDEO_FILE_ID` относится к исходному финальному MP4 из конца воронки. Использовать этот ключ для первого GIF нельзя, иначе последний шаг начнёт выдавать другой ролик.

## Разборы 01/10–10/10: MP4 уже привязаны

В v4.28 десять отдельных Telegram MP4-документов уже указаны в коде для всех десяти разборов. **Не добавляй их в VIDEO_FILE_ID:** этот ключ нужен только финальному исходному ролику. При первом показе каждого из десяти уроков бот пытается получить соответствующий MP4 через Telegram API и отправить его как зацикленную анимацию с **полным текстом и кнопкой**. Полученный animation ID сохраняется в памяти текущего процесса. При перезапуске Render потребуется повторная конвертация.

Переменные Render `STEP_ANIMATION_01`, `STEP_ANIMATION_02`, `STEP_ANIMATION_03`, `STEP_ANIMATION_04`, `STEP_ANIMATION_05`, `STEP_ANIMATION_06`, `STEP_ANIMATION_07`, `STEP_ANIMATION_08`, `STEP_ANIMATION_09` и `STEP_ANIMATION_10` для этих источников не требуются. Для всех десяти шагов исходные MP4 уже привязаны; переменные STEP_ANIMATION_NN остаются необязательным способом переопределения источника.

При ошибке загрузки или конвертации бот безопасно покажет текст и кнопку; техническая ошибка будет в Render Logs.

## Анимированные разборы: GIF + весь текст + кнопка

Начиная с v4.28 каждый из десяти экранов может отправляться **одним Telegram-сообщением**: сверху GIF/зацикленный MP4 без аудио, под ним полный текст в подписи и кнопка перехода к следующему разбору. Ограничение Telegram на подпись к анимации составляет 1024 символа после разбора форматирования; текущие десять текстов в этот лимит помещаются. Заголовок и номер разбора сохранены в подписи. Если у конкретного экрана пока нет GIF либо отправка анимации даёт ошибку, бот отправляет привычный текст с той же кнопкой.

**Как загружать анимации для любого разбора:**

1. Подготовь короткий MP4 без звуковой дорожки (или GIF), желательно 3–5 секунд и до 15 МБ.
2. **Просто отправь видео или файл боту с подписью `/stepgif 4`**, где цифра соответствует номеру разбора. Отдельное сообщение писать больше не требуется. Старый способ остаётся: отправь MP4, затем **ответь на него отдельным сообщением** `/stepgif 4`.
3. Бот покажет предварительный просмотр анимации и пришлёт её **Telegram ID**. Этот шаг только создаёт ID, а не подключает GIF к воронке.
4. Перешли ID с номером разбора в ChatGPT. Там он будет добавлен в исходный код через GitHub, без ручной настройки Render. Альтернативно можно прописать `STEP_ANIMATION_04` в Render → Environment, указав выданный ID анимации.

**Важно:** цифра, уже нарисованная на GIF, должна совпадать с цифрой команды. Например для `04/10` нужна команда `/stepgif 4`, а не `/stepgif 5`. Старые ролики могут содержать старое название внутри изображения; теперь в тексте сообщений используется `МИФ`. Чужие пользователи могут получать ID, но команда ничего не меняет в коде или настройках действующей воронки. После привязки и деплоя соответствующий экран появится с анимацией, полным текстом и кнопкой.

Telegram `file_id` применим к файлам именно этого бота, и отдельно размещать MP4 в GitHub не нужно. Для шагов 01–10 исходные MP4-документы уже привязаны. Если у любого шага отсутствует GIF или загрузка дала ошибку, остаётся обычный текст с кнопкой.
